分镜表

十五个镜头，七个节气

分镜表是拍摄前的施工图：每一格写清楚画面里有什么、镜头怎么动、怎么接到下一个镜头、旁白说什么、耳朵里听见什么。下面这张表和上面的播放器读的是同一份数据，点缩略图就从那个镜头开始播。

景别：离得多远

大远景→远景→全景→中景→近景→特写

越远越交代环境，越近越盯住细节。片子在“天”“山”这样的大远景和“一片叶子”“一个字”的特写之间来回走。

运镜：摄影机怎么动

推是靠近，拉是退远，摇是机位不动、镜头转向，移是机位平移，升是往上走。在代码里它们都只是一次缩放或平移。

转场：镜头怎么接

叠化是前一个画面慢慢溶进后一个；黑场是先暗下去再亮起来；匹配剪辑是用形状相同的东西把两个镜头接起来，比如第 7、8 镜的月亮接月饼。

    制作

    每一帧，都是时间的函数

    播放器不是在“放”一段录好的视频，而是每一帧都现算：给它一个时间 t，它就画出那一刻的画面。所以可以随便拖动，也可以一帧一帧地导出成视频文件。

    分镜就是一份数据

    每个镜头是一条记录：时长、景别、运镜、转场、字幕的起止时间、声音说明，外加一个画面函数。播放器按时长把镜头首尾相接，转场时两个镜头同时画，再按比例叠在一起。

    { id: 'jujube', term: '白露', dur: 12,
  scale: '近景', move: '固定，敲击后下摇',
  trans: { type: 'fade', d: 1.0 },
  lines: [[0.6, 4.2, '白露这天早上，枣叶上挂满了露水。'], …],
  draw: sJujube }

    运镜是坐标变换

    所有画面都画在 1280×720 的虚拟坐标里。“推”就是随时间放大，“摇”就是平移。远山、屋顶这些背景分成几层，远的层移动得少、近的层移动得多，一平移就有了纵深，这叫视差。

    随机，但每次都一样

    落叶、鸽群、槐花、山上成千上万棵树，都来自带种子的伪随机数。每片叶子在时刻 t 的位置是一个算式，而不是一帧一帧模拟出来的，所以跳到任何时刻都能直接算出那一帧。

    声音也是算出来的

    古筝用 Karplus–Strong 算法：一小段噪声在很短的延迟线里反复取平均，高频慢慢衰减，听起来就像拨了一下弦。鸽哨是几个频率相差几赫兹的正弦波一起响，互相“打架”出嗡嗡的拍频。风、蝉鸣、扫帚声都是滤过波的噪声。

    导出成真正的视频

    render.mjs 用 Playwright 在无头浏览器里打开这一页，按每秒 30 帧逐帧调用画面函数，交给 ffmpeg 编码；音轨用 OfflineAudioContext 一口气渲染出来，最后合成一个 MP4。

    npm install playwright
node beijing-autumn/render.mjs --out beijing-autumn.mp4
